# `f5.ts` — purpose twin

## Role

The voice-cloning provider for `audio.tts`. F5-TTS is the
open-weight flow-matching TTS that clones a target voice from a
short reference clip — the distinguishing capability over Kokoro
(preset voices) and Web Speech (browser voices). Runs locally,
typically through the VRM AI bridge at port 8000 (see
`docs/LOCAL_SERVICES.md`). v0.1 ships as an env-shape-only stub.

## Public surface

- `speakF5(req, options?)` — promise-returning speak. Currently
  throws "not implemented" with the resolved base URL in the
  message.
- Type: `F5ProviderOptions` — `{ voice?, referenceAudio? }`.

## Internal

- `F5_DEFAULT_BASE_URL = "http://localhost:8000"` — the VRM AI
  bridge per the local-services map. If F5-TTS is deployed
  separately later, override via the `F5_BASE_URL` env.
- Env read is `envOrUndefined` (same logic as `kokoro.ts`): local
  providers default to a documented localhost URL; explicit env
  is only needed to override.

## Why we ship a stub

- Zero-shot voice cloning is the medium-term path to a
  character-driven Aura voice without paying ElevenLabs per
  utterance. Reserving the slot now means the dialogue layer can
  already write `provider: "f5"` against the type.
- The service isn't reachable from a deployed Vercel build, but
  the type-check + the routing path are valuable on their own.

## Eventual call shape (documented, not implemented)

```
POST {F5_BASE_URL}/api/tts/f5
Headers: Content-Type: application/json
Body: { text, voice, reference_audio }
Response: audio/wav buffer
```

The reference clip is resolved server-side (a path on the
Hangar's filesystem, or a URL the bridge can fetch). The browser
does not upload audio to the bridge in v0.1 — that lands when the
calibration UX does.

## Depends on

- `lib/env.ts` — `envOrUndefined` for the optional base URL.
- `lib/state/audio.ts` — `TTSRequest`, `TTSResult` types.

## Does not

- **Does not call the F5 service.** Throws "not implemented".
  v0.1 is env-shape-only.
- **Does not upload reference audio.** The clip is referenced by
  path/URL, resolved server-side. Client-side upload is a future
  capability.
- **Does not detect service availability.** A future capability
  will probe; v0.1 fails fast with a clear error.
- **Does not stream.** F5-TTS supports chunked streaming; the
  wiring commit can opt into it. v0.1 throws before this matters.

## Bordering files

- `./web-speech.ts` — the working baseline provider; same surface.
- `../tts.ts` — the capability that routes by `provider: "f5"`.
- `./elevenlabs.ts`, `./kokoro.ts` — sibling stubs, same shape.
- `lib/env.ts` — typed env helpers.
- `docs/LOCAL_SERVICES.md` — bridge port map.
