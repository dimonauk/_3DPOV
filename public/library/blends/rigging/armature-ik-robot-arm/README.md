# Armature Constraints + IK — Stylised Robot Arm
**Blender 5.1 · Rigging · CC0**

A two-bone IK chain (upper_arm → lower_arm) where the end-effector tracks an
`IK_Target` empty in real time. A `IK_Pole` empty locks the elbow direction and
prevents solver flip. The robot arm mesh uses a single object with two vertex
groups for clean glTF skinning export.

```bash
# Step 1: build the scene
blender --background --python blueprint.py

# Step 2: record the viewport animation
blender robot_arm_ik.blend --background --python record.py
```

## Key techniques

### chain_count
The IK constraint lives on `lower_arm`. `chain_count=2` drives `lower_arm` and
its parent `upper_arm`. Setting `chain_count=0` would drive all ancestors up to
the root — useful for full-body IK but expensive on long chains.

### Pole target
Without a pole target, the IK solver has infinitely many valid solutions (the
elbow can orbit a full cone around the shoulder–wrist axis). The `IK_Pole` empty
breaks this symmetry: the solver bends the elbow toward the pole. Move IK_Pole
to −Y to keep the elbow pointing backward; move it to +Y to flip the elbow
forward. The `pole_angle` parameter rotates the local bone axis relative to the
pole vector — −90° matches the zero-roll bones used here.

### Vertex groups vs bone envelopes
The mesh uses two named vertex groups (`upper_arm`, `lower_arm`) and an Armature
modifier with `use_vertex_groups=True`. This is the only skinning mode that
writes correct joint weights to the glTF `JOINTS_0` / `WEIGHTS_0` accessors.
`parent_type='ARMATURE'` in Python uses bone envelopes instead and should be
avoided for GLB export.
