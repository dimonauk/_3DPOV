# EEVEE Next — Volumetric Light Cone + Bloom

**Blender 5.1 · Category: lighting · Licence: CC0**

Crossing warm-amber and cool-teal spot lights scatter through a Principled
Volume World, producing visible god-ray cones via EEVEE Next's voxel-grid
frustum sampler.  Bloom post-processing makes the lights flare against the dark
interior.  A secondary transparent emission-cone mesh provides a GLB-exportable
beam proxy for WebXR targets.

## Files

| File | Purpose |
|------|---------|
| `blueprint.py` | Full bpy scene build + EEVEE Next configuration |
| `record.py` | Camera-orbit animation render (240 frames, 24fps) |
| `SCREEN-RECORDING-NOTES.md` | OBS instructions for screen.mp4 |
| `volumetric_light_cone.blend` | Saved Blender scene (generated by blueprint.py) |
| `volumetric_light_cone.glb` | Exported GLB with fake-cone emission meshes |

## Key technique

EEVEE Next traces camera rays through a **voxel-grid frustum**, sampling the
Principled Volume shader at each tile.  The cone shape appears because the spot
light's shadow map occludes the volume outside the beam — without
`use_volumetric_shadows = True` the scatter appears as a uniform ambient haze
with no directional shafts.

The `Anisotropy` parameter controls Mie forward scatter:

| Value | Effect |
|-------|--------|
| 0.0 | Isotropic — even haze, no visible beam |
| 0.6 | Moderate forward bias — beam clear from most angles (this blueprint) |
| 0.9 | Strong forward bias — beam only visible looking toward the light |

**Fake emission cone (WebXR export):**  EEVEE Next volumes are GPU shader data
that cannot be embedded in glTF 2.0.  The blueprint builds a transparent-emission
truncated cone mesh at each light position (`blend_method = BLEND`,
`Fac = 0.11`) to carry the visual impression of the shaft into Three.js or
Babylon.js WebXR scenes.  The real-time engine sees an emissive, alpha-blended
cone rather than a volume.

## Running

```bash
# Build the scene and export GLB
blender --background --python blueprint.py

# Generate the orbit animation (requires the blend from step above)
blender --background volumetric_light_cone.blend --python record.py
```

## Tile size vs quality trade-off

| `volumetric_tile_size` | Cost | Result |
|------------------------|------|--------|
| `"2"` | Highest | Smooth, soft cones — use for final renders |
| `"4"` | Medium | Slightly blocky edges — fine for viewport scrubbing |
| `"8"` | Low | Visible tile artefacts — animation playback only |
| `"16"` | Fastest | Debug only |
