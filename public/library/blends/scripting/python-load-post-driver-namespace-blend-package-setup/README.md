# Python: bpy.app.handlers.load_post + bpy.app.driver_namespace
## Production .blend Asset Package — Open-File Setup Hooks and Custom Driver Expressions
**Blender 5.1 · Holoflow Studio · CC0**

---

### What this does

Registers three lifecycle hooks on a Blender `.blend` file so it behaves like a
self-configuring production package:

| Handler | Fires when | Does |
|---|---|---|
| `load_post` | .blend opens | Configures EEVEE samples, stamps version |
| `render_pre` | F12 or CLI render | Validates settings, aborts if misconfigured |
| `save_post` | File > Save | Increments a save counter |

Also populates `bpy.app.driver_namespace` with three pure-math callables
(`hs_breathe`, `hs_blink`, `hs_orbit`) so FCurve driver expressions can call
them by name — no variable setup required in the driver UI.

### Quick start

```
1. Open Blender 5.1 → Scripting workspace.
2. Text > Open → blueprint.py → Alt+P (Run Script).
3. Open holoflow_package_demo.blend.
4. In Python Console: bpy.app.driver_namespace["hs_breathe"]
   → confirms load_post fired and the function is registered.
5. Play the timeline — the crystal Z-scale oscillates via hs_breathe(frame, ...).
```

---

### Key concept: @bpy.app.handlers.persistent

Without this decorator every handler is wiped when a new `.blend` loads.
With it, the function stays in the list for the entire Blender session.
The correct way to survive file opens is to register driver_namespace *inside*
a persistent `load_post` handler — that way the functions are always available
no matter which file the artist opens.
