# Action Slots — Multi-ID Shared Action (Blender 5.1)

**Topic:** animation · **Type:** blend  
**Blender version:** 5.1  
**Licence:** CC0

## What This Is

A complete Python blueprint that demonstrates the Blender 5.0+ **Action Slots** system — the redesign that allows a single Action data-block to carry animation channels for multiple different IDs simultaneously.

Before 5.0, sharing an Action between a character body and a handheld prop meant either (a) separate Actions (two NLA strips, synchronisation headache) or (b) one Action with all channels mixed together (data-path collisions, hard to read in the Dope Sheet). 5.0 solves both by introducing *slots* — each slot is a named, ID-typed container routing FCurves to exactly one animatable object.

## Scene Contents

| Object | Blender Type | Slot id_type | Notes |
|--------|-------------|--------------|-------|
| `body_rig` | Armature | `OBJECT` | 2-bone forearm; forearm rotates 0→60°→0° |
| `sword_prop` | Mesh / Cube | `OBJECT` | Rises 0.4 m on frame 20, returns frame 50 |
| `face_mesh` | Mesh (shape keys) | `KEY` | `jaw_open` + `brow_raise` shape keys |

## Running

1. Open Blender 5.1, switch to the Scripting workspace.
2. Open `blueprint.py`, click **Run Script**.
3. Three objects appear; play the animation to verify independent slot playback.
4. Run `record.py` to render `viewport.mp4`.
5. Follow `SCREEN-RECORDING-NOTES.md` to capture `screen.mp4` with OBS.

## Key Python API (5.0+)

```python
action = bpy.data.actions.new("perf_01")

slot_arm  = action.slots.new("OBJECT", "body_rig")
slot_prop = action.slots.new("OBJECT", "sword_prop")
slot_key  = action.slots.new("KEY",    "face_mesh_keys")

arm_obj.animation_data_create()
arm_obj.animation_data.action      = action
arm_obj.animation_data.action_slot = slot_arm  # routing

# keyframe_insert() routes automatically via action_slot
arm_obj.pose.bones["forearm"].keyframe_insert("rotation_euler", frame=30)
```
