# GN Points to Volume + Volume to Mesh — Procedural Organic Coral Blob

**Blender 5.1 | CC0 | geometry-nodes**

A GN modifier chain that converts icosphere vertex positions into an OpenVDB
density field (Points to Volume) and then extracts an organic faceted mesh from
that field via marching cubes (Volume to Mesh). The result resembles sea coral
or an alien sponge: 42 Gaussian kernels splatted at icosphere-vertex positions,
fused at the core, protruding as tips — all with no hand-sculpting.

## Running

```bash
blender --background --python blueprint.py
blender --background organic_coral.blend --python record.py
```

## Key parameters (top of blueprint.py)

| Constant | Default | Effect |
|---|---|---|
| `ICO_SUBDIVISIONS` | 1 | 0=12 fat blobs, 1=42 coral branches, 2=162 fine tips |
| `VOXEL_SIZE` | 0.06 m | finer=smoother but slower; keep POINT_RADIUS ≥ 3× this |
| `POINT_RADIUS` | 0.32 m | Gaussian half-width; larger=more fusion between tips |
| `THRESHOLD` | 0.08 | lower=fatter; ~1.0=only dense core survives |
| `ADAPTIVITY` | 0.45 | 0=smooth marching-cubes, 1=blocky faceted |

## Volume pipeline constraints

- Volume is a **distinct geometry type** — mesh nodes cannot operate on it.
  The chain must be `Mesh → Points → Volume → Mesh` in strict order.
- Volume to Mesh with `resolution_mode='GRID'` inherits the incoming VDB
  voxel resolution; do **not** set a second Voxel Size here or you will
  resample and lose detail.
- Marching cubes produces **no UV coordinates**. Use world-space procedural
  shading (as in `coral_mat`) or bake normals+colour before export.
- `export_attributes` is unnecessary for this asset (no custom attributes);
  `export_apply=True` is **required** — runtimes do not evaluate GN.
