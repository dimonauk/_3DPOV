# GN Sort Elements — Sequential Face Reveal

**Blender 5.1 · Geometry Nodes · CC0**

`GeometryNodeSortElements` reindexes all elements of a domain by a float sort
weight, so that downstream `InputIndex` reads the sort rank rather than the
original mesh order. This tutorial sorts an icosphere's 80 triangular faces by
centroid Z (ascending), giving each face a bottom-to-top activation index.
A per-face delay timer (`face_rank × DELAY_FRAMES`) drives a clamped
`SceneTime.Frame` ramp that extrudes faces along their normals and colours them
dark-to-cyan-to-white. The result is a 130-frame bottom-to-top shell-unfurl
animation fully driven by the node graph with no keyframes.

## Key Parameters

| Constant | Default | Effect |
|---|---|---|
| `ICO_SUBDIVISIONS` | 2 | 80 triangular faces |
| `DELAY_FRAMES` | 1.5 | Gap between adjacent rank activations |
| `RAMP_FRAMES` | 8.0 | Per-face extrusion transition length |
| `EXTRUDE_HEIGHT` | 0.55 | Maximum outward displacement |
| `EXPORT_FRAME` | 70 | ~58 % of faces fully out |

## How to Run

```bash
blender --background --python blueprint.py
blender --background sequential_face_reveal.blend --python record.py
```

## Key Concept

Sort Elements changes the **domain element order globally** — not just within
one node. All downstream `InputIndex`, `FieldAtIndex`, and `AccumulateField`
calls see the **sorted indices**, not the original mesh indices. This differs
from `AccumulateField.Sort Index`, which reorders only within that node's
prefix sum computation.
