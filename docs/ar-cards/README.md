# AR Business Cards — operator guide

A multi-tenant AR business card stack: physical cards have a QR; scanning it loads `/c/<slug>` on this site; on phone, the page offers two AR modes — **image-tracked** (camera sees the card, 3D content overlays on it) and **world-placed** (tap to drop the model into your room). One JSON file per holder; all assets generated by `pnpm run cards:build <slug>`.

Production domain: **holoflow.co.uk** · registrar: **Namecheap** · host: **Vercel**

## What's installed

| Package | Role |
|---|---|
| `mind-ar@1.2.5` | Browser image-tracking (Three.js mode). Patched for Three r152+ color management — see `patches/mind-ar.md`. |
| `@google/model-viewer@4.2.0` | iOS Quick Look (USDZ) + Android Scene Viewer (GLB) world-placement. |
| `qrcode@1.5.4` | SVG QR generation. |
| `sharp@0.34.5` | Server-side image decode/encode (also used as a `canvas` replacement for MindAR compilation, since `canvas` doesn't have Node 24+ prebuilt binaries). |
| `@types/qrcode@1.5.6` | dev-only |

```
  model.usdz                            iOS Quick Look (TODO — generate from GLB)

```

## Add a new card holder

1. **Create their JSON** at `data/cards/<slug>.json` — copy `dimona.json`, edit fields. Slug must be `[a-z0-9-]+`.

2. **Drop in their card-front image** (optional). If `public/cards/<slug>/card-front.png` already exists when you run the build, it's preserved. Otherwise a procedural placeholder is generated from the brand colours in the JSON.

3. **Drop in their GLB model** (optional). If `public/cards/<slug>/model.glb` exists, it's preserved. Otherwise a pink-octahedron placeholder is generated.

4. **Build the assets:**
   ```bash
   PUBLIC_BASE_URL=https://holoflow.co.uk pnpm run cards:build <slug>
   ```
   Runs in 15-30 seconds depending on machine — MindAR compilation is the slow step (CPU-bound feature extraction).

5. **(Recommended)** Generate iOS USDZ from the GLB. Quickest path: open `model.glb` in Reality Composer (Mac) or use Blender's USD exporter (Blender 4.2+). Drop the result as `model.usdz` in the same directory. Without USDZ, iOS users skip Quick Look and fall back to the 3D preview tab.

6. **Test locally:** visit `http://localhost:5310/c/<slug>` and `/c/<slug>/card`.

7. **Commit and deploy** — see Deployment section below.

## How the AR modes pick themselves

`components/ar/ARLandingClient.tsx` does user-agent sniffing on the client:

| Device | Default tab | Reason |
|---|---|---|
| iOS Safari / Chrome on iOS | `world` | Safari has no WebXR; iOS rejects most MindAR setups. Quick Look (USDZ) is the only fully-native AR path on iOS. |
| Android Chrome | `mindar` | ARCore works, Scene Viewer works, MindAR works — image tracking is the "wow" moment we lead with. |
| Desktop browsers | `desktop` | No camera-AR makes sense; show interactive 3D preview only. |

Users can switch tabs at any time. Tabs visible per device:
- iOS / Android: `Card AR` (MindAR) · `Place in space` (model-viewer) · `3D preview`
- Desktop: `Place in space` · `3D preview` (no MindAR tab)

## Print pipeline

`/c/<slug>/card` renders both sides of the card at exact print dimensions (85×55mm trim + 3mm bleed + 4mm safe). Each card has a red-striped bleed area as a sanity check.

To produce print-ready files:
1. Open `/c/<slug>/card` in Chrome (font rendering is most predictable there)
2. File → Print → "Save as PDF"
3. **Scale: 100%** (no "Fit to page")
4. Paper: A4 portrait, Margins: default

The PDF will have one front + one back card centered on A4. Send to your printer with bleed instructions. Most print shops accept this format directly; some prefer separate PDFs per side.

For higher-volume printing, generate a layout sheet (multi-card per A4) — see `TODO.md` under "scripts/ar-layout-print-sheet.mjs".

# Deployment: Vercel + Namecheap + holoflow.co.uk

The full public-facing AR card story requires a domain anyone can hit — tailnet URLs (`*.tail99b2a4.ts.net`) only work for people on your tailnet. Production lives on Vercel with `holoflow.co.uk` (registered at Namecheap).

## Step 1 — first-time deploy via Vercel CLI

The CLI deploys the working directory directly; no GitHub push required. (You can wire up GitHub later for auto-deploy on push.)

```powershell
cd D:\The_Hangar\apps\production\holo-flow-studio

# Authenticate once — opens browser, sign in with email/GitHub/Google
vercel login

# Link this directory to a new Vercel project — answer the prompts:
#   "Set up and deploy?"  → Y
#   "Which scope?"        → (your personal account)
#   "Link to existing?"   → N
#   "Project name?"       → holo-flow-studio  (this is also the *.vercel.app subdomain)
#   "Code directory?"     → ./  (current dir)
#   "Modify settings?"    → N  (vercel.json + next.config.mjs already configured)
vercel

# After preview deploy succeeds, promote to production
vercel --prod
```

Vercel returns a URL like `https://holo-flow-studio.vercel.app/` and `https://holo-flow-studio-<hash>.vercel.app/`. Visit `/c/dimona` on either to confirm the AR pipeline works on Vercel before pointing the domain at it.

## Step 2 — environment variables

```powershell
# In the project dir:
vercel env add PUBLIC_BASE_URL production
# When prompted, paste: https://holoflow.co.uk
# Apply to: Production only

vercel env add PUBLIC_DOMAIN production
# Paste: holoflow.co.uk

# Re-deploy to pick up new env vars
vercel --prod
```

Or set these via the Vercel dashboard: **Project → Settings → Environment Variables**.

## Step 3 — attach the domain in Vercel

1. Open your Vercel project → **Settings → Domains**
2. **Add Domain** → type `holoflow.co.uk` → Continue
3. Vercel offers two configurations:
   - **Apex + redirect www → apex** (recommended; "holoflow.co.uk" is shorter for printing)
   - Or "www.holoflow.co.uk as primary, apex redirects to www"

Pick **apex as primary**. Vercel will then show two DNS records you need to add at Namecheap.

## Step 4 — Namecheap DNS records

1. Log in to **Namecheap → Domain List → holoflow.co.uk → Manage**
2. Click the **Advanced DNS** tab (NOT the "Domain" tab — that's WHOIS)
3. Under **Host Records**, **delete any existing default Namecheap "parking page"** records (usually a CNAME for `www` pointing to `parkingpage.namecheap.com` and a URL Redirect on `@`)
4. Add these two records:

| Type             | Host  | Value                    | TTL       |
|------------------|-------|--------------------------|-----------|
| **A Record**     | `@`   | `76.76.21.21`            | Automatic |
| **CNAME Record** | `www` | `cname.vercel-dns.com.`  | Automatic |

The `@` symbol = the apex domain (holoflow.co.uk itself). Note Namecheap stores the CNAME value with a trailing dot — paste it as shown; their UI may strip the dot, that's fine.

5. **Save All Changes** (button at the bottom of the records list)

6. Back in Vercel, the domain entries will go from "Invalid Configuration" → "Pending" → "Valid" as DNS propagates. Typical Namecheap propagation: **5-30 minutes**. Worldwide: up to 24 hours but usually much faster.

## Step 5 — verify TLS + final smoke test

Once Vercel reports the domain "Valid":

```powershell
# Verify cert + reachability
curl -I https://holoflow.co.uk/
curl -I https://holoflow.co.uk/c/dimona
curl -I https://www.holoflow.co.uk/   # should 308 redirect to apex

# Real test
start https://holoflow.co.uk/c/dimona
```

If you get `ERR_CERT_AUTHORITY_INVALID` for the first few minutes, that's Let's Encrypt issuing — wait 2-3 mins and refresh.

## Step 6 — regenerate the production QRs and re-deploy

Your local QRs were generated against the placeholder URL during development. Regenerate against the real domain:

```powershell
$env:PUBLIC_BASE_URL = "https://holoflow.co.uk"
pnpm run cards:build:all
vercel --prod
```

The QRs now encode the correct production URL. Print the new ones (open `/c/<slug>/card` in Chrome, File → Print).

## Step 7 — turn on Git auto-deploy (optional, recommended)

CLI deploys are great for first launch but stop being practical when you're iterating. To get push-to-deploy:

1. `cd` to the studio dir, `git init && git add . && git commit -m "Initial commit"`
2. Create a private repo on GitHub: `https://github.com/new` (name: `holo-flow-studio`)
3. Push: `git remote add origin git@github.com:<you>/holo-flow-studio.git && git push -u origin main`
4. In Vercel: **Project → Settings → Git → Connect Git Repository** → pick the GitHub repo
5. From then on, every `git push` deploys a preview; pushes to `main` deploy to production

## Email on holoflow.co.uk (separate from web hosting)

Vercel handles `holoflow.co.uk` for the *web*. Email is separate. Namecheap offers:
- **Private Email** (paid, ~$10/yr) — full mailbox for `hello@holoflow.co.uk`
- **Email Forwarding** (free) — forwards `hello@holoflow.co.uk` → your existing Gmail/Outlook

For free forwarding: Namecheap → Domain List → holoflow.co.uk → Manage → **Redirect Email** tab → add forwarder. (You'll also need MX records — Namecheap adds these automatically when you enable Email Forwarding from their UI.)

The `vCard` URL on each card encodes the email address; pick the path you want before printing cards.

## Ongoing development

- Use `pnpm dev` (port 5310). Hot-reload picks up route changes; static assets in `public/cards/<slug>/` need a manual page refresh.
- Card holder JSON changes don't auto-refresh — the loader uses `fs.readFile` which Next caches per-request in dev. Hit the URL again after editing the JSON.
- `target.mind` compile is the slowest step (~10-30s). Use `pnpm run cards:build <slug> --skip-mind` during iteration if you're only tweaking layout/QR/JSON.

## Known issues

1. **`canvas` package on Node 24+:** doesn't ship prebuilt binaries; `npm install canvas` will fail to build natively on Windows without Cairo. Worked around in `scripts/ar-compile-mind.mjs` by subclassing MindAR's `CompilerBase` and providing a sharp-backed fake canvas.

2. **mind-ar 1.2.5 + Three.js r152+:** legacy `sRGBEncoding` / `LinearEncoding` / `outputEncoding` removed. Patched in `node_modules/mind-ar/dist/mindar-image-three.prod.js` via string replacement. Auto-reapplies on every `pnpm install` via the `postinstall` script (so Vercel builds get the patch too).

3. **USDZ on Windows:** no good native path. For now generate USDZ on Mac or via Blender 4.2+ USD exporter. Vercel build can be extended with a Linux serverless function using Apple's open-source `usd_from_gltf` if needed.

4. **Sharing protected models:** the demo GLB is a procedurally-generated placeholder. The real model files committed to `public/` are visible to anyone who scans the QR — don't put unwatermarked, unreleased work in there. For licensed content, host the GLB on a separate authenticated origin and update `card.ar.model` to the signed URL.
